# PX4 Calibration Web & pre-arm bench workflow

This is a localhost-only ROS 2 Humble web dashboard for Cube/Pixhawk stock PX4.
No firmware flashing, vehicle arm, mission modification, parameter write or
motor movement is performed through its HTTP API.

## MiniPC1

```bash
cd /home/otomasi/Project/px4-ros
./build.sh
source ./env.sh
ros2 launch px4_mission_foxglove mission_foxglove.launch.py \
  start_usb_bridge:=true start_calibration_web:=true
```

Open **http://127.0.0.1:8093** in MiniPC1's browser.

On another computer, establish an SSH tunnel (replace the MiniPC's network
name/address as required):

```bash
ssh -L 8093:127.0.0.1:8093 otomasi@minipc1
```

Then open **http://127.0.0.1:8093** on the remote computer. The web server
intentionally does not bind to `0.0.0.0`. Do not expose it via a public
unauthenticated reverse proxy.

The page provides four tabs:
- **Ringkasan**: MAVLink USB, armed state, flight mode, GPS, estimator,
  IMU, battery, gyro/accel/compass identification, and VESC motor isolation.
- **Kalibrasi**: gyro, 6-face accelerometer, compass, level orientation
  steps. Progress and PX4 STATUSTEXT events are displayed; command
  responses must not be mistaken for fully verified calibration.
- **Parameter PX4**: asynchronous read-only, categorized parameter inventory.
- **Pre-arm & log**: PX4's `MAV_CMD_RUN_PREARM_CHECKS (401)`, check results,
  operator checklist and STATUSTEXT. No `MAV_CMD_COMPONENT_ARM_DISARM (400)`
  is exposed through HTTP.

## Optional physical calibration

**Disabled by default.** For later isolated-bench calibration only, both
independent gates must be deliberately enabled at launch:

```bash
ros2 launch px4_mission_foxglove mission_foxglove.launch.py \
  start_usb_bridge:=true \
  web_calibration_enabled:=true px4_calibration_enabled:=true
```

No motors, drivetrain/ESC power or other actuators may be energized during
sensor calibration. The page requires a second explicit action and operator
confirmation `MOTORS_ISOLATED`, connected and disarmed PX4. A rejected
command, unsupported firmware and unsuccessful calibration must be shown as
such. Never send ESC calibration or bypass/force-arm commands from the web.

Supported sensor calibration protocol uses `MAV_CMD_PREFLIGHT_CALIBRATION`:
gyro (param1=1), compass (param2=1), accel (param5=1) and level (param5=2).
These are deliberately validated and allowlisted in `pixhawk_bridge`. Do not
start two concurrent calibrations, and use actual PX4 messages to guide
six-face orientation changes.

## No RC receiver — ROS control authority

The rover has no RC telemetry receiver. The ROS integration no longer
requires `rc_telemetry_fresh` for read-only mission previews. The supervisor
and VESC drive gate use an independent ROS operator heartbeat topic
`/pixhawk/operator/heartbeat` (`std_msgs/Bool`), with a 300 ms timeout.
**Its authority remains unverified by default**. No automatic heartbeat is
generated by this dashboard, and publishing a Boolean from software cannot
replace a hardwired emergency stop or prove safe human override.

PX4 stock v1.17 supports `COM_RC_IN_MODE=1` for MAVLink joystick-only
control and `4` to disable manual input entirely. The last option removes
manual control and MUST NOT be chosen without an independent E-stop and
valid data-link-loss protections. Neither this project nor the web changes
`COM_RC_IN_MODE` on the physical Cube automatically. Configure after
explicit testing with hardware outputs isolated and keep PX4 failsafes on.

In PX4 AUTO.MISSION, local GPS can be temporarily absent only for modes
that do not require global navigation; it cannot deliver a valid GPS waypoint
mission without a trustworthy position estimate. Arming without GPS under
`COM_ARM_WO_GPS=1` is not equivalent to autonomous navigation readiness.

Before physical ARM:
1. Select a matching PX4 rover airframe with actuator mapping verified.
   The PX4 v1.17 rover guide lists `50000` differential and `51000`
   Ackermann, **but those IDs require the correct Rover PX4 firmware build**.
   Check compatibility with the current Cube FMUv2 firmware before changing
   `SYS_AUTOSTART`.
2. Diagnose missing accelerometer/compass calibration and calibration
   status, especially `CAL_ACC0_ID=0` and `CAL_MAG0_ID=0`.
3. Determine valid mode requirements and navigation sensors; wait until
   estimator health meets the selected mode's constraints.
4. Commission safe ROS operator override and an independent physical E-stop.
5. Disconnect/isolate motor supply, fix the rover on a bench, and verify
   PX4 can pass all pre-arm checks. Only then consider a separately authorized
   **non-forced** physical ARM and prompt DISARM test.

## Additional advisory-speed safeguard

When the Pixhawk airframe is uninitialized, its VFR_HUD telemetry briefly
reported a physically implausible `129.7 m/s` groundspeed for this rover.
The ROS safety supervisor now treats speed above its configured
`max_plausible_speed_mps=8.0` as invalid and latches STOP rather than using
the corrupted value for wall-follower guidance. This is a software
sanity check only, not verified wheel odometry.
