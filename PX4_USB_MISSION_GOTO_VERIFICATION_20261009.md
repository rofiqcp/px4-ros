## What is necessary for physical Mission/GOTO

1. Identify exact `AUTOPILOT_VERSION` from the current Cube using a single-owner MAVLink router or coordinated read-only bridge restart. No flashing.
2. Confirm installed firmware actually supports Differential Rover; current 732-param snapshot has **zero RD_* and zero CA_* params**, and read-only RD_WHEEL_TRACK request timed out. PX4 differential rover docs require a suitable rover build; `SYS_AUTOSTART=50000` is **not** a universal conversion switch.
3. Complete physically measured wheel track, left/right wheel actuator assignments, ESC direction/neutral, independent E-STOP, and direct RC transmitter/receiver with MANUAL mode takeover.
4. Prove valid GPS/localization, loaded and verified mission, arrival tolerance, manual takeover and stop behaviour with wheels physically off the ground for bench tests.
5. Stage and independently approve all hardware parameter writes and motor tests; read back every applied parameter. Do not enable automatic arming in the ROS bridge without a clear physical test corridor, operator, receiver and hardware stop.
6. Only then test live GOTO of a safely bounded local target, continuous telemetry and abort/RC takeover; measure actual odometry/arrival and failure cases.
7. Existing bridge deliberately guards these actions while required safety conditions are not met.
